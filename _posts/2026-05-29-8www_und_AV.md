# 1. World Wide Web (WWW)

### 🌍 URL (Uniform Resource Locator)
- Aufbau:
  - scheme>://<host>:<port>/<path>?<search>

- Beispiel:
  - <http://www.example.com/index.html>


👉 definiert **Ort + Zugriffsmethode**

## 2. HTML, XML

### 📄 HTML
- Beschreibung von Webseiten (Darstellung)
- Tags:
  - `<B>`, `<I>`, etc.

### 📦 XML
- strukturierte Datenbeschreibung

## 3. HTTP (Hypertext Transfer Protocol)

### 📡 Eigenschaften
- Request/Response zwischen Client und Server
- basiert auf TCP (Port 80)
- zustandslos  

---

### 📥 HTTP Methoden
- `GET` → Webpage lesen holen
- `Put`-> Webpage speichern
- `POST` → Daten senden, Ausgabe von Info an Server, z.B. Formulare, Annotationen. 
- `HEAD` → Metainfo der Webpage lesen
- `Move, Copy`, `DELETE`

---

### 📦 Nachrichtenformat

#### Request:

```
GET /index.html HTTP/1.1
Host: ...
Header...
```

#### Response:

```
HTTP/1.1 200 OK
Header...
Body...
```

👉 Aufbau:

```
method/version - URL/status - version/phrase
header - value
leerzeile
header - value
cr,lf
body
```
  
### HTTP Caching
- Lokal durch Browser
- Proxies (nicht transparent, TCP bis Proxi, dann neue TCP Verbindung zu Server)
- Transparentes Caching
  - Router filtern req und weiterleiten an Cache
  - Cache-hierarchien, kooperatives Caching
- Caching durch Angabe von Ablauf- und Modifikationsdatum im Header unterstützen. 

### Passwort-Auth
1. Client sendet req an Server
2.- Anwtort leerer Body, Status-Code, dass auth required
3. Client antwortet mit auth-header (Username und Password)
4. Caching und Anhängen der weiteren Requests an den betreffenden Server

### Content Distributed Networks CDN
Platzieren nahe bei den Anwendern. URL Rewriting, HTTP redirection.
- Vorteile
  - Vermeiden von hoher Server-auslastung
  - Reduktion von Netzlast
  - Reduktion von Antwortzeiten

### Web services
- WSDL zur Beschrebung von Operationen (RPC)
- SOAP Nachrichten mit Signatur etc, für HTTP
- REST

## 4. HTTP Versionen

### 🟢 HTTP/1.0
- **nicht persistent**
- jede Anfrage → neue TCP-Verbindung (jedes objekt z.B. Bild)
  - Overhead nebst Get+Response gibt's SYN, SYN+ACK, FIN. 
- Per object cost: 1 RTT (TCP handshake) + 1 RTT (HTTP request/response) = 2 RTTs in HTTP/1.0

---

### 🔵 HTTP/1.1
- **persistent connections**
- mehrere Requests pro Verbindung
- Pipelining
- Z.B für HTML file 1 RTT und für 4 images und CSS file  1 RTT, und für ipeline 1 RTT, macht total 3 RTT.  

---

### 🟣 HTTP/2
- Multiplexing (mehrere Streams gleichzeitig)
- Header-Kompression
- Server Push
- Server sendet daten ohne anfrage an den Client, weil Server weiss, dass
der Client diese benötigen wird.

---

### HTTP basierte Protokollarchitektur
- Narrow Waist
  - IP -> (HTTP, TLS, TCP, IP)
  - Narrow waist = one universal layer (IP)
  - Narrow waist: Protokolle die in jedem Endsystem immer wieder implementiert werden.

### 🟠 HTTP/3 (QUIC)
- basiert auf UDP
- schneller Verbindungsaufbau
- kein Head-of-Line Blocking
- integrierte Verschlüsselung (TLS 1.3)
